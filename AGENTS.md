# AGENTS.md

Общие правила проекта для ИИ-агентов и ассистентов разработки (Claude Code, Codex, Cursor и др.). Правила конкретного инструмента — в его файле, например [CLAUDE.md](CLAUDE.md).

Moscow Epidemic Sim — хобби-игра на Godot: вымышленная респираторная инфекция распространяется по реальной карте Москвы и пояса ~30 км за МКАД. Каждый житель — отдельный синтетический агент. Две стороны: мэр и болезнь. Платформы: сначала Mac и ПК (Windows), затем iOS.

Репозиторий: https://github.com/BolotovKonstantine/moscow-epidemic-sim · этапы: https://github.com/users/BolotovKonstantine/projects/7

## Планируемый стек и структура

- `game/` — Godot 4, 2D, GDScript: интерфейс, карта, сессия, мост к ядру (`scripts/sim_bridge/`). Renderer-кандидат — Compatibility.
- `native/` — расчётное ядро на C++ через GDExtension (`src/`, `include/`, `godot_bridge/`).
- `game/sim/` — малая простая эталонная реализация модели для проверки ядра на маленьких сценах.
- `tools/city_pipeline/` — Python: OSM/GIS → версионированный городской пакет.
- `data/manifests/` — в Git; `data/raw/`, `data/processed/`, `data/packages/` — вне Git (см. `.gitignore`).
- `tests/model/`, `tests/scenarios/`, `tests/integration/`, `benchmarks/`.
- Сценарии — JSON с версией схемы и валидацией.

Полное дерево — в [docs/architecture.md](docs/architecture.md). Создавай каталоги по мере реальной необходимости, а не заранее пустыми. При создании `game/`, `native/` или `tools/city_pipeline/` добавь туда свой `AGENTS.md` с командами сборки, запуска и тестов этого модуля и `CLAUDE.md` с одной строкой `@AGENTS.md`.

Зафиксированы Godot 4.7.2, эталонный Mac (M1, 16 ГБ), правило границы региона и срез данных около 2020–2021. Эталонные ПК и iPhone, список архитектур, сезон и длительность сценария пока открыты (decisions.md) — если задача от них зависит, спроси автора.

## Инварианты модели (нарушать нельзя)

- **Каждый житель — индивидуальный агент** со стабильным ID, профилем и состоянием. Не заменять когортами, выборкой с весами или дробными заражёнными. Один нулевой пациент остаётся одним человеком.
- **Ядро не зависит от отображения**: камера, зум, FPS и отрисовка не меняют результат. Весь регион считается даже вне экрана. Скорость игры меняет число интервалов в секунду, а не параметры модели.
- **Жители, здания и контактные группы — данные, а не Godot Nodes.** Никаких Node/Sprite на жителя; точки рисуются пакетно (MultiMesh по участкам). Ядро не трогает сцены и UI.
- **Память ядра**: структура массивов (SoA), компактные целочисленные коды, общие таблицы профилей. Никаких строк, словарей и объектов на человека в массовой части.
- **Без O(N²)**: контакты только внутри конкретных мест и групп поездок. Метро за сутки — не один общий пул; люди в разных машинах — не контактная группа.
- **Риск**: `P = 1 − exp(−Σ λ·Δt)`, λ в 1/час. Не хранить «вероятность на шаг» при смене шага. Один контакт — один механизм передачи (рёбра и смешение одной ситуации не складывать). Эффект меры не применять дважды.
- **Состояния болезни**: `S, E, Ip, Ia, Is, V, H, R, D`; разрешены только переходы `S→E, E→Ip, Ip→Ia, Ip→Is, Ia→R, Is→R, Is→V, V→H, V→R, V→D, H→R, H→D`. Изоляция, выявление и очередь — отдельные флаги, не стадии. Нехватка коек не блокирует развитие тяжёлой болезни; очередь не удаляет пациентов.
- **Наблюдение ≠ истина**: мэр видит выявленные случаи с задержкой; истинные ряды хранятся отдельно.
- **Детерминизм**: состояния на начало интервала, стабильный порядок событий по (время, ID), порядок обхода групп не влияет на результат, отдельные потоки RNG по подсистемам. Сохранение включает состояние RNG, а не только seed.
- **Население сохраняется** при всех переходах; умершие остаются в учёте и не ездят; госпитализированные не ездят в офис.
- **Оптимизация проверяется эталоном**: биномиальная выборка и прочие ускорения допустимы только при доказанной эквивалентности индивидуальному перебору на малых сценах.

Список обязательных проверок математики, мер и производительности — в [docs/roadmap.md](docs/roadmap.md); новые механики должны сопровождаться соответствующими тестами-инвариантами.

## Данные

- Различай три вида значений: **наблюдаемые** (источник + дата), **оценённые** (метод + неопределённость, метка `estimated`), **игровые настройки**. Не выдавай оценки и игровые параметры за статистику.
- Отсутствие значения → `unknown`, оценка с методом или явный параметр. Нет данных о койках ≠ ноль коек.
- Каждый источник регистрируется карточкой происхождения (`source_id`, URL, владелец, лицензия, даты, покрытие, формат, контрольная сумма, версия обработки).
- Координаты хранятся в WGS84; длины, площади и буферы считаются в метрической проекции.
- Большие выгрузки и собранные пакеты не коммитить. В Git — манифесты, скрипты получения и небольшие разрешённые тестовые наборы.
- OSM: атрибуция и ODbL. Не скачивать массово тайлы `tile.openstreetmap.org` — собственные тайлы из разрешённых данных.
- Население только синтетическое; никаких персональных данных реальных людей. Параметры COVID-19 (Covasim и др.) не переносить в вымышленную болезнь.

## Соглашения

- Документация, комментарии к проектным решениям, Issues и описания PR — на русском. Имена файлов, каталогов и идентификаторы в коде — на английском.
- Меняя поведение, которое описано в `docs/`, обновляй соответствующий документ в том же изменении. Новые подтверждённые решения и открытые вопросы — в [docs/decisions.md](docs/decisions.md).
- Предположения модели явно отделяй от наблюдаемых данных (в коде, конфигурации и документах).
- Крупные новые механики сначала согласовывай с автором (Issue) — масштаб первой версии ограничен числом механик, а не территорией. Отложенное (пробки, вакцинация, 3D, мультиплеер, несколько инфекций и т. п.) не реализовывать без запроса.
- Цели производительности (60 FPS ПК / 30 FPS телефон, игровые сутки за 5–15 с) — инженерные цели, не результаты; не заявлять их достигнутыми без замеров с указанием устройства, сборки, seed и версии пакета.
## Git и GitHub

- Вклад — через ветку и pull request (см. [CONTRIBUTING.md](CONTRIBUTING.md)); не коммитить прямо в `main` без просьбы автора. Коммитить и пушить — только когда автор об этом просит.
- Имена веток: `<тип>/<кратко>` — `docs/…`, `feat/…`, `fix/…`, `data/…`, `chore/…`.
- Сообщения коммитов — на русском, в повелительном наклонении («Добавить…», «Исправить…»), первая строка до ~70 символов.
- Описание PR: что изменилось, зачем, как проверялось (как требует CONTRIBUTING.md).
- Для операций с GitHub используй `gh`. Этапы и задачи — в [GitHub Project](https://github.com/users/BolotovKonstantine/projects/7).
- Не коммитить секреты, `.env`, большие данные и сгенерированные артефакты сборки (`.godot/`, `build/`, `exports/`, нативные бинарники).

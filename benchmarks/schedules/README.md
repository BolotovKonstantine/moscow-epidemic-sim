# Замер расписаний и движения всего региона (#43)

Жители и места всего пакета, шаблоны расписаний и посещения, регулярные поездки с учётом загрузки, затем сутки движения всего населения часами сессии по 300 с: рейсы с вместимостью и вагонами, очереди, отмены, внешнее состояние. Правила — [docs/population.md](../../docs/population.md#расписания) и [docs/mobility.md](../../docs/mobility.md#реализация-43), код — `native/src/core/mobility.cpp`, `schedule.cpp`, `session_trips.cpp`.

## Запуск

```sh
benchmarks/schedules/run.sh [каталог пакета] [seed] [потоки] [суток] [каталог хранилища] [предел кеша путей, МиБ]
```

По умолчанию — `data/packages/moscow-2021-0.7.0`, seed населения 20261013 (seed сессии — seed + 6: места, расписания и рейсы), все ядра, 7 суток с понедельника, хранилище `data/processed/session-store` (вне Git), предел кеша 256 МиБ (предложение #35). Первый запуск назначает места (#41) и планирует поездки с учётом загрузки и пишет их в хранилище, повторный читает их с диска. Скрипт собирает release-сборку чистого ядра через CMake и печатает устройство, ОС, коммит, отчёт в JSON и вывод `/usr/bin/time -l`. В отчёте по каждым суткам — итоги состояний каждые 3 часа (`hours`, столбцы — `hours_columns`), поездки по видам, посадки, не поместившиеся при приходе рейса, отмены, восстановленные пути, события. Код возврата 1 — численность не сошлась хотя бы на одном интервале или есть нарушения.

## Результат

MacBook Pro M1 (MacBookPro17,1), 16 ГБ, macOS 26.5.1, от сети; release (`-O3` CMake Release), 8 потоков для подготовки, движение — в одном потоке; ядро 0.1.0, пакет `moscow-2021` 0.7.0, 17 286 718 жителей, 575 438 зданий, seed 20261013, seed сессии 20261019, нулевые сутки — понедельник, интервал 300 с. Коммит сборки — 574b10b плюс изменения ветки `feat/core-schedules`, 19 октября 2026. Прогоны: первый запуск с пределом кеша 2048 МиБ (места уже в хранилище) и двумя сутками, затем повторный запуск с диска и неделей.

## Выводы

- **Инварианты держатся на всём регионе**: каждый житель в одном состоянии, численность сходится, вместимость не превышена, итоги ритма — будни и выходные, ночные смены (1,05–1,35 млн на местах ночью вместе с застрявшими, см. ниже), посещения днём.
- **Предел кеша 256 МиБ не годится для движения.** Регулярным поездкам нужно 12,1 млн путей (882 МБ): утро и вечер — разные ключи (ячейка дома и ячейка места). С пределом 256 МиБ первый прогон восстанавливал вытесненные пути по одному в основном потоке (~1 мс на путь), и сутки не досчитались за 30 минут; с 2048 МиБ восстановлений нет. Предел — предложение #35, его выбор — за автором: поднять до ~1 ГиБ (+0,6 ГБ), либо заранее строить пути следующего периода пакетом в нескольких потоках, либо укрупнить ячейку.
- **Время первого старта — ~22 минуты против цели 1–2 минуты** (решение 2 по #35). Почти всё — итерации учёта загрузки: штраф раздувает стоимость перегруженных перегонов, и деревья остановок просматривают больше узлов. Повторный старт с диска — ~16 с (цель «секунды при повторном» почти достигнута). Рычаги из решения автора: меньше итераций (без итераций — один проход, перегрузка 23,7% вместо 16,6%) или итерации по укрупнённым ячейкам.
- **Скорость движения — ~50 с на будний игровой день в один поток** против цели 5–15 с; выходные — 14–15 с. Основная работа — 85 млн событий жителей в будни. Рычаги — параллельный расчёт событий (в #49 и далее), меньше пеших участков по событию.
- **Перегрузка — калибровка, а не дефект** (решение 3 по #35): 4 млн отмен в будни, 0,6 млн жителей в возвращении в 9:00; отменивший поездку обратно остаётся на месте до следующих суток (правило эталона: другого пути после предела ожидания нет до #44), отсюда около 0,35 млн «ночующих на работе» сверх ночных смен. Доли видов, интервалы и вместимость калибруются в #44.

# Часы и очередь событий ядра (#40)

Замер календарной очереди событий и часов чистого C++ ядра ([#40](https://github.com/BolotovKonstantine/moscow-epidemic-sim/issues/40)) на полном населении. Правила очереди — [docs/sim-core.md](../../docs/sim-core.md#время-и-очередь-событий), код — `native/src/core/event_queue.cpp` и `native/include/mesim/sim_clock.h`, инструмент — [event_queue.cpp](event_queue.cpp). Пакет не нужен: нагрузка синтетическая, по числу жителей пакета.

## Что меряется и проверяется

- **Модельные сутки** — нагрузка прототипа [#33](../core_contract/README.md): у каждого жителя 4 события (выход 6–10 ч, затем по очереди долгий и короткий промежуток), продвижение `SimClock::advance_to` интервалами по 300 с до 48 ч. Время, пик памяти очереди (`EventQueue::memory_bytes` в конце каждого интервала: `next_event` и ёмкость корзин), прирост `phys_footprint`. Повтор даёт ту же контрольную сумму последовательности.
- **Далёкие события** — у каждого жителя событие через 2–30 суток, каждое ставит следующее так же, горизонт 60 суток. Нагрузка суточных корзин и их раскладки по минутным при сдвиге горизонта (как будущие переходы болезни этапа 4).
- **Массовый перенос** — у всех жителей событие в пределах суток, четыре раунда переноса всех событий на случайное время в пределах трёх суток (в том числе за горизонт кольца): число сжатий и пик памяти. Затем перенос пятой части без срабатывания порога и одно явное сжатие (время), после — исполнение очереди.
- Порядок (время, ID) проверяется на каждом событии, все события исполнены, после исполнения ключей не осталось. Нарушение — ненулевой код возврата.

Время включает модельный обработчик: розыгрыш Philox и случайный доступ к массиву состояния жителя на каждом событии. Розыгрыши — поток расписаний (`RngStream::schedules`), seed по умолчанию 20261019.

## Запуск

Из корня репозитория:

```sh
benchmarks/event_queue/run.sh               # 17 286 718 жителей, seed 20261019
benchmarks/event_queue/run.sh 1000000 7     # другое число жителей и seed
```

## Результаты

### 19 октября 2026, эталонный Mac

MacBook Pro 13" M1, 16 ГБ, macOS 26.5.1, от сети. Release-сборка CMake (`-O3`, clang Command Line Tools), ядро 0.1.0, один поток. Код — ветка `feat/core-clock` поверх `f8f21f9`, три прогона подряд. 17 286 718 жителей (`moscow-2021` 0.7.0), seed 20261019, интервал 300 с.

| | Значение |
| --- | --- |
| Модельные сутки, 69 146 872 события | 6,08–6,56 с (повтор — 5,89–6,12 с) |
| Пик памяти очереди на сутках | 321,0 МБ: `next_event` 69,1 МБ + корзины ~252 МБ |
| Далёкие события, 60 суток, 58 451 348 событий | 5,07–5,70 с, пик 313,5 МБ |
| Массовый перенос: 4 × 17,3 млн переносов | 7,92–8,26 с, 15 сжатий |
| Пик памяти при массовом переносе | 347,8 МБ (до переноса — 258,0 МБ) |
| Одно сжатие, 3 457 056 устаревших ключей | 0,44–0,46 с |
| Очередь после сжатия | 207,5 МБ — ровно `next_event` и один ключ на жителя |
| Пик процесса (все фазы подряд) | RSS 851–883 МБ |

Контрольная сумма суток `0e79182e39131f32` совпала во всех прогонах и повторах.

**Профиль суток** (`sample`, 3 с во время суток): около половины времени — сама очередь (извлечение 15 %, сортировка минутных корзин 24 %, постановка 6 %), остальное — модельный обработчик: Philox и промахи кеша по массивам жителя. Значит, очередь сама по себе стоит ~2,8 с на сутки — на уровне прототипа #33 (3,8 с вместе с розыгрышами, без часов, проверки устаревших ключей и `next_event`).

## Выводы

- Очередь укладывается в бюджет памяти sim-core.md: пик ~250 МБ корзин против 270 МБ прототипа, `next_event` — колонка жителя из бюджета 36 байт. Массовый перенос всех событий не раздувает очередь больше чем на ~35 %: сжатие держит устаревшие ключи не выше четверти живых, а после сжатия остаётся ровно по ключу на сущность.
- Далёкие события на недели вперёд не замедляют очередь: 58 млн событий за 60 суток — 5 с, сутки с ~1 млн событий — меньше 0,1 с.
- Одно сжатие на полном населении — около 0,45 с. Сжатие срабатывает по порогу, поэтому разовая команда мэра, переносящая события всех жителей, стоит ~2 с переносов и сжатий; это пауза расчёта, а не кадра интерфейса (расчёт в отдельном потоке, sim-core.md).
- Сутки очереди с модельным обработчиком — ~6 с. Это нижняя граница игровых суток без движения, контактов и снимков; цель «сутки за 5–15 с» проверяется замером #49 на полном движении.

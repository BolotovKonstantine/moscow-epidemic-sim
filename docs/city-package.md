# Формат паспорта городского пакета

На этапе 0 реализован паспорт версии 1, на этапе 1 в него добавлена роль `zones`: JSON с описанием региона, происхождением данных и перечнем файлов. Схема и CLI находятся в `tools/city_pipeline/`. Паспорт не содержит население или геометрию целиком: большие данные лежат рядом отдельными файлами, а проверка SHA256 читает их блоками.

Паспорт создаёт контракт между подготовкой данных и будущим загрузчиком игры. С этапа 1 пайплайн собирает реальный пакет (см. «Файлы пакета этапа 1»); загрузчик Godot и бинарные форматы для игры ещё не реализованы. Успешная проверка паспорта не означает, что пакет готов к игровой партии.

## Поля паспорта версии 1

| Поле | Значение |
| --- | --- |
| `schema_version` | Целое число 1; несовместимая версия отклоняется |
| `package_id`, `package_version` | Идентификатор пакета и версия его содержимого |
| `kind` | `fixture` для технического примера, `city_data` для подготовленных городских данных |
| `description` | Описание покрытия и назначения |
| `created_at` | Время создания с часовым поясом |
| `builder` | Имя и версия инструмента подготовки |
| `region` | Правило региона, 30 км буфера, системы координат и ссылка на файл границы |
| `sources` | Карточки происхождения исходников |
| `assets` | Файлы пакета, их роли, размеры, хеши и связи с источниками |

Схема: [city-package-v1.schema.json](../tools/city_pipeline/schemas/city-package-v1.schema.json). Поля с неизвестными именами отклоняются, чтобы опечатка не выглядела принятой настройкой. Версия схемы независима от версий пакета, ядра и Godot.

## Регион и координаты

`region.rule` фиксирует правило `moscow_admin_union_mkad_outer_buffer`; `buffer_meters` равен 30000. `storage_crs` — `EPSG:4326`, порядок географических координат — долгота, широта. `metric_crs` описывает выбранную метрическую проекцию обработки. `boundary_asset_id` указывает на существующий элемент `assets` с ролью `boundary`.

Это декларация правил обработки. Валидатор паспорта не проверяет геометрию; построение контура проверяет сборщик: проекция должна быть метрической, площадь внутри МКАД — в заданном диапазоне (850–900 км²), регион — содержать территорию внутри МКАД. Буфер 30 км и объединение с административной Москвой проверяются тестом на синтетическом городе.

В тестовом примере паспорта проекция обозначена как не выбранная: метрические операции в нём не выполняются. Реальный пакет `moscow-2021` использует `EPSG:32637`, контуры из OSM на 2021-01-01 и указывает источники и даты. Сезон и длительность игрового сценария паспорт не задаёт; они будут частью отдельной конфигурации сценария.

## Источники и файлы

Каждая карточка источника содержит ID, тип `external` или `synthetic`, URL, владельца, лицензию, дату данных, время получения, покрытие, формат, SHA256 исходника и версию обработки. Неизвестная дата данных обозначается `null`; хеш и лицензия необходимы для подготовленного пакета и не заменяются выдуманными значениями.

Файл содержит ID, роль, относительный путь, формат, размер в байтах, SHA256 и ссылки на источники. Путь записывается с `/` относительно каталога паспорта. Абсолютные пути, `..`, обратные слеши, неоднозначные компоненты и ссылки за пределы пакета не принимаются. Большие исходные выгрузки не обязаны лежать в пакете: их хеш сохраняется в карточке происхождения.

`data_kind` разделяет `observed`, `estimated` и `game_setting`. Для `estimated` обязательны `estimation.method` и `estimation.uncertainty`. Синтетический источник не может обосновывать файл с видом `observed`. Неизвестные значения внутри будущих таблиц должны иметь явное представление; их правила появятся вместе с форматами таблиц.

Роли файлов: граница, здания, дороги, транспорт, учреждения, население, зоны (`zones`, добавлена на этапе 1; прежние паспорта остаются корректными) и отчёт качества. Набор доступных слоёв может быть неполным на промежуточных этапах. Валидатор не объявляет такой пакет играбельным и не подставляет отсутствующие слои нулевыми значениями.

## Проверки

CLI проверяет версию и обязательные поля, даты, уникальность ID и путей, связи с источниками и файл границы. В полном режиме дополнительно проверяются наличие, размер и SHA256 всех перечисленных файлов. JSON с повторяющимися ключами, NaN и Infinity отклоняется.

`--metadata-only` позволяет проверить паспорт до размещения больших файлов. Вывод явно указывает, что содержимое файлов не проверялось. Геометрия, связность графа, лицензирование производной базы и качество населения этой командой не подтверждаются.

Команды установки, проверки и тестов приведены в [AGENTS.md пайплайна](../tools/city_pipeline/AGENTS.md).

## Файлы пакета этапа 1

Промежуточные форматы: CSV и GeoJSON по одному объекту в строке, сжатые gzip без имени и времени в заголовке; координаты WGS84 с 7 знаками. Порядок строк — по стабильным ID. ID зданий и учреждений — ID OSM с префиксом типа (`w123`, `r456`, `n789`), рёбер дорог — `<way>:<номер участка>`, зон — `g<ix>_<iy>` (индексы квадрата 1 км в метрической проекции), маршрутов и stop_area — `r<relation>`.

| Файл | Роль · вид | Содержимое |
| --- | --- | --- |
| `boundary.geojson` | boundary · game_setting | Три объекта: `region` (граница пакета), `moscow_admin`, `mkad_outer`; площади в км² |
| `buildings.geojsonl.gz` | buildings · observed | Контуры зданий и исходные теги `building`, `building:levels`, `height`, `name` |
| `building_attributes.csv.gz` | buildings · estimated | Зона, Москва/пояс, внутри МКАД, площадь основания, этажность и её источник (`tag` — `building:levels` одним числом без округления, дробные сохраняются, `height` — высота в метрах или футах / 3 м, `default` — оценка по типу здания, в том числе при неоднозначных значениях вроде `3;5`), площадь этажей, источник функции (`tag`, `tag+poi` — основная функция по тегам, вторичные доли по точкам внутри, `poi`, `site`, `unknown`; функциональный тег самого здания вроде `shop` при `building=apartments` даёт вторичную функцию), доли функций `residential`, `work`, `retail`, `education`, `medical`, `transport`, `control`, `other` |
| `population.csv.gz` | population · estimated | Жители здания (целое), зона и основной метод распределения. Сетка населения обязана быть в EPSG:4326; ячейки без данных внутри региона считаются пропуском покрытия (проверка `raster_covers_region`), а не нулём |
| `roads.geojsonl.gz`, `road_nodes.csv.gz` | roads · observed | Рёбра между пересечениями: класс, одностороннее движение (1, −1, 0), длина в метрах, мост, тоннель, уровень; узлы с компонентами связности |
| `transit_stops.csv.gz`, `transit_routes.csv.gz`, `transit_segments.csv.gz` | transport · estimated | Остановки, маршруты с упорядоченными остановками, отрезки между соседними остановками (расстояние по прямой). Соседние в маршруте точка остановки и платформа ближе 100 м (или с одним именем ближе 400 м) — одна остановка во всех маршрутах (представитель группы — точка остановки, иначе меньший ID); если маршрут перечисляет сначала все точки, потом все платформы, берётся более полный список. Объединение — эвристика по порогам конфигурации, поэтому эти файлы, внешние входы и связи зон помечены `estimated`; все исходные ID OSM объединённой остановки — в колонке `osm_ids` файла остановок |
| `transit_transfers.csv.gz` | transport · estimated | Пересадки внутри stop_area с модельным временем; платформа, объединённая с точкой остановки, представлена этой точкой |
| `transit_service.json` | transport · game_setting | Модельные интервалы по виду транспорта и периоду суток |
| `gateways.csv.gz` | transport · estimated | Внешние входы. `road` — точка пересечения границы региона ребром дороги, заходящим внутрь (касание границы снаружи не считается, у участка вдоль границы учитываются только его концы; строка на точку; `inside_ref`/`outside_ref` — концы ребра по сторонам границы, могут быть пустыми). `transit` — остановка маршрута в регионе, соседняя по маршруту с остановкой снаружи; ненайденные члены маршрута выходом не считаются |
| `facilities.csv.gz` | facilities · estimated | Медицина, образование и полиция, чья представительная точка лежит в регионе, с привязкой к зданиям; вместимость `unknown`. Одно учреждение, нанесённое точкой, контуром здания и участком одного вида, объединяется по самому большому (в метрах) контуру; все ID OSM — в `osm_ids`. Объединение и `building_ids` — пространственная эвристика, поэтому файл помечен `estimated`. Координаты учреждения-территории — вычисленная точка внутри контура, у учреждения-здания — точка здания, у точки — координаты узла |
| `zones.geojsonl.gz` | zones · estimated | Контур зоны, доли Москвы и территории внутри МКАД, жители, здания, здания без функции, жилая площадь, остановки и учреждения |
| `zone_links.csv.gz` | zones · estimated | Связи зон по видам: `road` — соседние зоны, границу между которыми пересекает ребро дороги внутри региона (ребро сначала обрезается границей; пересечения с линиями сетки вычисляются точно, поэтому учитываются все промежуточные зоны длинного ребра; проход ровно через угол даёт диагональную пару; участки вне региона связей не дают); `connections` — число таких рёбер, `min_length_m` — длина самого короткого. Для транспорта — зоны соседних остановок маршрута, они не обязаны соседствовать |
| `quality_report.json`, `quality_report.md` | quality_report · observed | Проверки, источники, пропуски, оценки, связность и выборка для ручной проверки |

Пустая ячейка CSV означает отсутствие значения (например, здание вне всех зон); `unknown` — явно неизвестное значение. Для синтетического пакета вид `observed` заменяется на `game_setting`, так как синтетика не является наблюдением.

## Синтетический пример

[manifest.json](../tests/fixtures/city_package/manifest.json) описывает небольшой вручную созданный квадрат в GeoJSON. Он помечен `fixture`, источник — `synthetic`, данные — `game_setting`. Это проверка формата файлов и хешей; квадрат не изображает границу Москвы, а дата примера не является решением о годе сценария.

# Формат паспорта городского пакета

На этапе 0 реализован паспорт версии 1, на этапе 1 в него добавлена роль `zones`, на этапе 2 — роль `map` (участки карты), на этапе 3 — роль `sim` (расчётные таблицы ядра): JSON с описанием региона, происхождением данных и перечнем файлов. Схема и CLI находятся в `tools/city_pipeline/`. Паспорт не содержит население или геометрию целиком: большие данные лежат рядом отдельными файлами, а проверка SHA256 читает их блоками.

Паспорт создаёт контракт между подготовкой данных и будущим загрузчиком игры. С этапа 1 пайплайн собирает реальный пакет (см. «Файлы пакета этапа 1»). Производные участки карты для отображения (`.mtile`, см. «Участки карты») входят в пакет с версии 0.2.0, игра умеет их читать. С версии 0.7.0 (#36) пакет содержит и расчётные таблицы ядра (`sim/`, роль `sim`, см. «Расчётные таблицы»); формат выбран в #33 и описан в [sim-core.md](sim-core.md#расчётный-пакет), загрузчик ядра — #37. Успешная проверка паспорта не означает, что пакет готов к игровой партии.

## Поля паспорта версии 1

| Поле | Значение |
| --- | --- |
| `schema_version` | Целое число 1; несовместимая версия отклоняется |
| `package_id`, `package_version` | Идентификатор пакета и версия его содержимого |
| `kind` | `fixture` для технического примера, `city_data` для подготовленных городских данных |
| `description` | Описание покрытия и назначения |
| `created_at` | Время создания с часовым поясом |
| `builder` | Имя и версия инструмента подготовки |
| `region` | Правило региона, 30 км буфера, системы координат и ссылка на файл границы |
| `sources` | Карточки происхождения исходников |
| `assets` | Файлы пакета, их роли, размеры, хеши и связи с источниками |

Схема: [city-package-v1.schema.json](../tools/city_pipeline/schemas/city-package-v1.schema.json). Поля с неизвестными именами отклоняются, чтобы опечатка не выглядела принятой настройкой. Версия схемы независима от версий пакета, ядра и Godot.

## Регион и координаты

`region.rule` фиксирует правило `moscow_admin_union_mkad_outer_buffer`; `buffer_meters` равен 30000. `storage_crs` — `EPSG:4326`, порядок географических координат — долгота, широта. `metric_crs` описывает выбранную метрическую проекцию обработки. `boundary_asset_id` указывает на существующий элемент `assets` с ролью `boundary`.

Это декларация правил обработки. Валидатор паспорта не проверяет геометрию; построение контура проверяет сборщик: проекция должна быть метрической, площадь внутри МКАД — в заданном диапазоне (850–900 км²), регион — содержать территорию внутри МКАД. Буфер 30 км и объединение с административной Москвой проверяются тестом на синтетическом городе.

В тестовом примере паспорта проекция обозначена как не выбранная: метрические операции в нём не выполняются. Реальный пакет `moscow-2021` использует `EPSG:32637`, контуры из OSM на 2021-01-01 и указывает источники и даты. Сезон и длительность игрового сценария паспорт не задаёт; они будут частью отдельной конфигурации сценария.

## Источники и файлы

Каждая карточка источника содержит ID, тип `external` или `synthetic`, URL, владельца, лицензию, дату данных, время получения, покрытие, формат, SHA256 исходника и версию обработки. Неизвестная дата данных обозначается `null`; хеш и лицензия необходимы для подготовленного пакета и не заменяются выдуманными значениями.

Файл содержит ID, роль, относительный путь, формат, размер в байтах, SHA256 и ссылки на источники. Путь записывается с `/` относительно каталога паспорта. Абсолютные пути, `..`, обратные слеши, неоднозначные компоненты и ссылки за пределы пакета не принимаются. Большие исходные выгрузки не обязаны лежать в пакете: их хеш сохраняется в карточке происхождения. Модельные параметры (интервалы движения, скорость пересадки) ссылаются не на OSM, а на синтетический источник `build-config-<package_id>` — саму конфигурацию сборки с её SHA256.

`data_kind` разделяет `observed`, `estimated` и `game_setting`. Для `estimated` обязательны `estimation.method` и `estimation.uncertainty`. Синтетический источник не может обосновывать файл с видом `observed`. Неизвестные значения внутри будущих таблиц должны иметь явное представление; их правила появятся вместе с форматами таблиц.

Роли файлов: граница, здания, дороги, транспорт, учреждения, население, зоны (`zones`), конфигурация сборки (`config`; обе добавлены на этапе 1), отчёт качества, участки карты (`map`, этап 2) и расчётные таблицы (`sim`, этап 3; не больше одного файла на пакет); прежние паспорта остаются корректными. Набор доступных слоёв может быть неполным на промежуточных этапах. Валидатор не объявляет такой пакет играбельным и не подставляет отсутствующие слои нулевыми значениями.

## Проверки

CLI проверяет версию и обязательные поля, даты, уникальность ID и путей, связи с источниками и файл границы. В полном режиме дополнительно проверяются наличие, размер и SHA256 всех перечисленных файлов, а для файла с ролью `map` — и индекс участков — те же требования, что у загрузчика игры: формат и его версия, совпадение пакета и версии с паспортом, атрибуция — подпись OSM и владелец с лицензией каждого внешнего источника паспорта, таблицы классов формата, непустой список без повторов, ровно один обзор (0, 0), номера участков не больше 2²⁰ по модулю, размер участка от 1 байта до 256 МиБ, `bbox` участка — упорядоченный прямоугольник с координатами не больше 10⁷ м по модулю или `null`, пути участков внутри каталога карты (по тем же правилам, что пути файлов паспорта), наличие, размер и SHA256 каждого участка; каждый участок разбирается (магия, заголовок — объект нужного формата и версии, только известные разделы с их типами, JSON без NaN и Infinity, числа `f32` конечные, смещения разделов внутри файла после заголовка и кратные 4, заявленные размеры — в том числе 16 МБ для JSON — и их сумма до распаковки, завершённый поток deflate) и его заголовок сверяется с индексом: пакет, уровень, номер, размер участка уровня, угол по сетке, `bbox` (у обзора — с ненулевой площадью), `counts` — объект, классы и атрибуция. Смысл массивов (индексы вершин, коды классов, подписи) проверяет загрузчик игры. Паспорт хранит хеш индекса, индекс — хеши участков, поэтому участки не перечисляются в паспорте поштучно. Для файла с ролью `sim` проверяются индекс и каждая расчётная таблица (см. «Расчётные таблицы»), а `package_id` и `package_version` должны помещаться в заголовок таблицы — это проверяется и с `--metadata-only`. JSON с повторяющимися ключами, NaN и Infinity отклоняется.

`--metadata-only` позволяет проверить паспорт до размещения больших файлов. Вывод явно указывает, что содержимое файлов не проверялось. Геометрия, связность графа, лицензирование производной базы и качество населения этой командой не подтверждаются.

Команды установки, проверки и тестов приведены в [AGENTS.md пайплайна](../tools/city_pipeline/AGENTS.md).

## Файлы пакета этапа 1

Промежуточные форматы: CSV и GeoJSON по одному объекту в строке, сжатые gzip без имени и времени в заголовке; координаты WGS84 с 7 знаками. Порядок строк — по стабильным ID. ID зданий и учреждений — ID OSM с префиксом типа (`w123`, `r456`, `n789`), рёбер дорог — `<way>:<номер участка>`, зон — `g<ix>_<iy>` (индексы квадрата 1 км в метрической проекции), маршрутов и stop_area — `r<relation>`.

| Файл | Роль · вид | Содержимое |
| --- | --- | --- |
| `boundary.geojson` | boundary · game_setting | Три объекта: `region` (граница пакета), `moscow_admin`, `mkad_outer`; площади в км² |
| `buildings.geojsonl.gz` | buildings · observed | Контуры зданий и исходные теги `building`, `building:levels`, `height`, `name` |
| `building_attributes.csv.gz` | buildings · estimated | Зона, Москва/пояс, внутри МКАД, площадь основания, этажность и её источник (`tag` — `building:levels` одним числом без округления, дробные сохраняются, `height` — высота в метрах или футах / 3 м, `default` — оценка по типу здания, в том числе при неоднозначных значениях вроде `3;5`), площадь этажей, источник функции (`tag`, `tag+poi` — основная функция по тегам, вторичные доли по точкам внутри, `poi`, `site`, `unknown`; функциональный тег самого здания вроде `shop` при `building=apartments` даёт вторичную функцию), доли функций `residential`, `work`, `retail`, `education`, `medical`, `transport`, `control`, `other` |

| `gateways.csv.gz` | transport · estimated | Внешние входы. `road` — точка пересечения границы региона ребром дороги, заходящим внутрь (касание границы снаружи не считается, у участка вдоль границы учитываются только его концы; строка на точку; `inside_ref`/`outside_ref` — концы ребра по сторонам границы, могут быть пустыми). `transit` — остановка маршрута в регионе, соседняя по маршруту с остановкой снаружи; ненайденные члены маршрута выходом не считаются |

Объединение и `building_ids` — пространственная эвристика, поэтому файл помечен `estimated`. | `zones.geojsonl.gz` | zones · estimated | Контур зоны, доли Москвы и территории внутри МКАД, жители, здания, здания без функции, жилая площадь, остановки и учреждения |
| `zone_links.csv.gz` | zones · estimated | Связи зон по видам: `road` — соседние зоны, границу между которыми пересекает ребро дороги внутри региона (ребро сначала обрезается границей; пересечения с линиями сетки вычисляются точно, поэтому учитываются все промежуточные зоны длинного ребра; проход ровно через угол даёт диагональную пару; участки вне региона связей не дают); `connections` — число таких рёбер, `min_length_m` — длина самого короткого. | `build_config.json` | config · game_setting | Точная копия конфигурации сборки, из которой собран пакет; её SHA256 совпадает с источником `build-config-<package_id>`, а URL источника указывает на файл в конкретном коммите (если он закоммичен без правок) |

## Участки карты

Формат версии 1 выбран в [#9](https://github.com/BolotovKonstantine/moscow-epidemic-sim/issues/9). Участки — производный слой только для отображения: они собираются из пакета и той же вырезки OSM, а модель их не читает. С версии пакета 0.2.0 (#13) `build` пишет участки всего региона в каталог `map/` пакета; `map-tile` по-прежнему делает тестовый экспорт вокруг точки или (с `--all`) тот же набор, что в пакете, в отдельный каталог (см. [tools/city_pipeline/AGENTS.md](../tools/city_pipeline/AGENTS.md)).

**Набор участков региона.** Обзор (уровень 0) и на уровнях 1 и 2 — каждый участок сетки, квадрат которого задевает границу региона, в том числе почти пустые у края: игра может считать отсутствующий в индексе участок лежащим вне региона. Правила покрытия проверяет экспорт и отказывается писать набор, если они нарушены; итоги — в отчёте качества (`map`):

- каждое здание пакета лежит ровно в одном участке 2 км — там, где его представительная точка; уникальные ID `pick.attrs` всех участков 2 км совпадают со списком зданий пакета (в участках 8 км мелкие здания не рисуются, см. таблицу уровней);
- каждое ребро `roads.geojsonl.gz`, кроме тоннелей, после обрезки по региону задевает хотя бы один участок 2 км и рисуется во всех участках, которые задевает (обрезанным по их квадратам); ребро с классом, которого нет в классах карты, — ошибка экспорта;
- каждая зона 1 км пакета задевает хотя бы один участок уровня 1 и уровня 2.

Для `moscow-2021` 0.2.0: 1 обзор, 150 участков 8 км и 2061 участок 2 км, всего 163 МБ (0.4.0 — те же участки, 176 МБ; 0.5.0 — с уровнями мостов #23, 173 МБ); индекс — 1,1 МБ (подробности и замер — в [AGENTS.md пайплайна](../tools/city_pipeline/AGENTS.md)). С версии 0.4.0 участки несут и данные слоёв карты (#16, см. «Слои по данным пакета» ниже); игра рисует их переключаемыми слоями с легендой (#16, см. [game/AGENTS.md](../game/AGENTS.md)).

**Плоскость.** Метрическая проекция пакета (`EPSG:32637`), 1 единица = 1 м, ось Y вниз. Начало `plane.origin_metric` — левый верхний угол, кратный 8 км. Координаты в плоскости карты: `x = E − x0`, `y = y0 − N`.

| Уровень | Участок | Содержимое | Упрощение |
| --- | --- | --- | --- |
| 0 | один на регион, начало (0, 0) | площади от 5 га, реки, магистрали (motorway, trunk, primary), магистральные железные дороги, границы региона и Москвы; с 0.4.0 — линии маршрутов электричек и метро, зоны 1 км, остановки и учреждения всего региона | 25 м |
| 1 | 8×8 км | площади от 2000 м², дороги до tertiary, реки, железные дороги, здания от 150 м²; с 0.4.0 — линии всех маршрутов | площади 3 м, линии 4 м, здания 2 м |
| 2 | 2×2 км | всё без упрощения; данные выбора зданий | нет |

Участок `(ix, iy)` уровня с размером `s` занимает в плоскости карты квадрат от `(ix·s, iy·s)`; сетки уровней вложены. Вершины участка хранятся относительно этого угла. Площади и линии обрезаются по границе региона и участка. Здание целиком принадлежит участку, где лежит его представительная точка (`lon`, `lat` из `building_attributes.csv.gz`), и может выступать за край — это учтено в `bbox`. Тоннели дорог, рек и железных дорог не рисуются; метро — отдельный слой транспорта.

**Мосты и эстакады** (#23, с версии пакета 0.5.0). У каждой линии подложки и дороги есть уровень рисования: 0 — земля, мост (`bridge` OSM, кроме `no`; у дорог — колонка `bridge` в `roads.geojsonl.gz`) — его `layer`, ограниченный 1–5 (мост без `layer` или с `layer` ≤ 0 — уровень 1). Не мост с `layer` > 0 остаётся на земле: на перекрёстках и примыканиях он сливается с другими дорогами, как в стиле OSM Carto. Линии участка идут по уровню, внутри уровня — по классу, затем по ключу; раздел `line.level` задаёт диапазон вершин и треугольников каждого уровня. Игра рисует уровни снизу вверх: внутри уровня — все обводки, затем все заливки (дороги сливаются), а следующий уровень целиком поверх: мост лежит над дорогой под ним и обведён тёмной обводкой. Порядок уровней общий для всех участков уровня подробности, поэтому на стыках участков он тот же. Конец линии на краю участка (линия обрезана и продолжается у соседа) не получает квадратного выступа, чтобы лента не ложилась на линии соседнего участка поверх их порядка рисования.

**Файл** `z<уровень>/<ix>_<iy>.mtile`: 8 байт `MESMTILE`, u32 версия формата, u32 длина заголовка, JSON-заголовок (UTF-8, дополнен пробелами до кратности 4), затем разделы. Числа little-endian; разделы идут сразу после заголовка, `offset` отсчитывается от начала файла и кратен 4. У раздела в заголовке: `name`, `dtype` (`f32`, `i32`, `json`), `shape` и `count` для массивов, `offset`, `size` (в файле), `raw_size` (после распаковки), `codec` — `deflate` (поток zlib, читается `PackedByteArray.decompress(raw_size, COMPRESSION_DEFLATE)`) или `none`. В заголовке также `package_id`, `package_version`, `level`, `tile`, `tile_size_m`, `origin` (угол в плоскости карты), `bbox` (в координатах участка), `classes`, `counts`, `attribution` — список: первая строка — подпись «© участники OpenStreetMap, ODbL», которую карта показывает всегда, затем владелец и лицензия каждого внешнего источника пакета из паспорта (для `moscow-2021` — OSM и GHS-POP: жители зданий в `pick.attrs` получены из сетки GHS-POP, CC BY 4.0).

Подписи участка принадлежат участку, где лежит их точка. Подпись вдоль линии ставится в середине самого длинного почти прямого отрезка (отклонение от хорды не больше 8 % половины его длины). Какие подписи видны, решает игра по теме, масштабу и пересечениям.

Классы (код — позиция в списке, список — в `classes` заголовка): площади `farmland, residential, commercial, industrial, cemetery, grass, park, forest, water`; здания `unknown, residential, work, retail, education, medical, transport, control, other`; линии `stream, river, service, pedestrian, residential, tertiary, secondary, primary, trunk, motorway, tram, rail_minor, rail, boundary_moscow, boundary_region`; подписи `capital, okrug, municipality, city, town, district, village, suburb, hamlet, river_major, river, water, street_major, street, metro, rail_station`; с 0.4.0 — линии маршрутов `bus, trolleybus, tram, train, subway`, остановки `platform, stop_position, station`, виды транспорта остановок (биты маски) `bus, share_taxi, trolleybus, tram, light_rail, monorail, train, subway`, учреждения `hospital, clinic, doctors, university, college, school, kindergarten, police`. Классы дорог — из `highway` (связки `*_link` — класс основной дороги; `unclassified`, `living_street`, `road` → `residential`). Подложка из OSM: `water` — `natural=water`, `waterway=riverbank`, `landuse=reservoir|basin`; `forest` — `landuse=forest`, `natural=wood`; `park` — `leisure=park|garden|golf_course`, `landuse=recreation_ground|village_green`; `grass` — `landuse=grass|meadow`, `natural=grassland|scrub|heath`; `river` — `waterway=river|canal`; `rail_minor` — `railway=rail` с `service` и `narrow_gauge`; `tram` — `railway=tram|light_rail|monorail`.

**Слои по данным пакета** (#16, с версии 0.4.0). Данные для переключаемых слоёв карты; что и как рисовать, решает игра по теме. Зоны, остановки и учреждения лежат только в обзоре: он загружен всегда, поэтому эти слои доступны при любом масштабе без подгрузки, а их объём для всего региона невелик (~8 тыс. зон, ~13 тыс. остановок, ~11 тыс. учреждений). Линии маршрутов (решение автора по #16, 11 октября 2026): метро — схема, прямые отрезки между соседними остановками маршрутов метро из `transit_segments.csv.gz` (пара остановок рисуется один раз в любом направлении); остальные маршруты — по путям (`way`) их отношений `type=route` в вырезке OSM, кроме членов с ролями остановок и платформ из конфигурации (`transit.stop_roles`, `platform_roles`, в том числе с номером «_N»), платформ и недостроенных или заброшенных путей; берутся только виды из `transit.route_modes` пакета, вид без класса линий карты — ошибка экспорта; тоннели рисуются — маршрут показывается непрерывным. Путь, по которому идут маршруты одного класса, рисуется один раз; маршрутка (`share_taxi`) — класс `bus`, монорельс и `light_rail` — класс `tram`. Пути маршрута за пределами вырезки в ней отсутствуют и не рисуются. Линии обрезаются по региону и участку, как дороги; в обзоре — только электрички и метро. Неизвестный вид остановки, транспорта или учреждения — ошибка экспорта. Таблицы классов новых слоёв в индексе необязательны (их нет у пакетов до 0.4.0), но `validate` требует таблицу, если в участке есть разделы слоя с её кодами. Жители зон и зданий, функции с `building.est = 1` — оценки пакета; остановки, учреждения и маршруты — данные OSM.

**Чтение в игре** — `game/scripts/map/` ([game/AGENTS.md](../game/AGENTS.md)): игра держит в памяти индекс и обзор, а участки 8 и 2 км читает по камере (#14) — только участки текущего уровня, задевающие окно с запасом; участок, которого нет в индексе, считается лежащим вне региона. Игра отклоняет индекс или участок другой версии формата, с SHA256, пакетом, уровнем или классами, не совпадающими с индексом, разделы, выходящие за файл или ссылающиеся на несуществующие вершины, и уровни линий `line.level` вне 0–5, с повторами, разрывами диапазонов или треугольниками чужого уровня — с понятным сообщением, без падения. Слои по данным пакета необязательны (в участках пакетов до 0.4.0 их нет), но если раздел слоя есть, слой должен быть полным: длины по вершинам и строкам, коды классов, строки зон и зданий, маски видов транспорта и значения (жители и площади не отрицательны, `building.est` — 0 или 1) проверяются; зоны, остановки и учреждения допускаются только в обзоре и внутри его охвата.

**Выбор здания в игре** (#15): клик на уровне подробности 2 ищет здание среди загруженных участков 2 км, чей охват зданий (`pick.bbox`) содержит точку, — здание может выступать за край своего участка. Попадание — точка внутри внешнего кольца `pick.ring`: внутренний двор считается частью здания. Если точка внутри нескольких зданий (наложенные контуры OSM), выбирается здание с наименьшей площадью внешних колец, при равенстве — с меньшим ID. Участки 2 км, чей охват в индексе задевает окно, загружаются, даже если их квадрат вне окна; пока такой участок, охват которого содержит точку, не подключён, клик выбор не меняет: иначе промах снял бы выбор, а победитель наложения зависел бы от порядка загрузки. Карточка показывает значения `pick.attrs` выбранного здания (связь с учреждениями — оценка пайплайна по контурам и точкам OSM); выбор хранит копию контура и значений и не теряется при выгрузке участка.

**Индекс** `index.json`: `format` = `mesim-map-index`, `format_version`, пакет и его источники, `metric_crs`, `plane`, `levels`, `classes`, `attribution` и список `tiles` с уровнем, индексами, путём, размером, SHA256, `bbox` в плоскости карты и счётчиками. Повторный экспорт из тех же файлов даёт те же байты. `map-tile` отказывается работать, если переданная конфигурация не совпадает с `build_config.json` пакета: вырезка OSM хранится по хешу конфигурации, и другая конфигурация подставила бы чужую вырезку или проекцию.

Контуры `boundary.geojson` округлены до 7 знаков WGS84; после перевода в метры у границы региона `moscow-2021` (0.1.0 и 0.2.0) есть микросамопересечение, поэтому карта исправляет контуры `make_valid`. На расчёты пакета это не влияет: они выполняются по исходной метрической границе.

## Расчётные таблицы

С версии пакета 0.7.0 ([#36](https://github.com/BolotovKonstantine/moscow-epidemic-sim/issues/36)) `build` пишет каталог `sim/`: таблицы `.mtab` версии 1 и индекс `sim/index.json`. Формат таблицы, метки, единицы и правила загрузки заданы контрактом [sim-core.md](sim-core.md#расчётный-пакет). Таблицы получаются из уже записанных файлов пакета (`tools/city_pipeline/simtables.py`), как участки карты, поэтому промежуточные CSV и GeoJSON остаются источником истины и происхождения. Модельные параметры поездок берутся из `model_assumptions.mobility` конфигурации сборки, итоги переписи — из таблиц Росстата (роли источников `census_*`, разбор — `census.py`); поэтому `build` требует конфигурацию версии 2 (`config_version` 2, схема `build-config-v2.schema.json`), а версия 1 остаётся для пакетов до 0.7.0. Оба решения автор принял 16 октября 2026 ([decisions.md](decisions.md)). Повторный экспорт из тех же файлов даёт те же байты.

**Индекс** `sim/index.json`: `format` = `mesim-sim-index`, `format_version` 1, `package_id`, `package_version`, `plane` (`origin_metric` — то же начало, что у карты, `metric_crs`, `units` = `cm`, `y_axis` = `down`), `zone_cell_m` (сторона квадрата зоны), `sentinels` (метки `none` и `unknown` для `u8`–`u64`), `codes` — таблицы кодов (код — позиция в списке) и `tables`. Таблицы перечислены ровно в порядке ниже. У каждой есть `name`, `path` (`<name>.mtab`), `schema_version`, `rows`, `size_bytes`, `sha256`, `data_kind`, `source_ids`, а у вида `estimated` — ещё `estimation` с методом и неопределённостью. В синтетическом пакете вид `observed` заменяется на `game_setting`.

Коды: `osm_type` — `n, w, r`; `territory` — `moscow, buffer`; `building_function` — классы зданий карты; `function_source` — `tag, tag+poi, poi, site, unknown`; `share_function` — порядок колонок долей; `road_class` — `service, pedestrian, residential, tertiary, secondary, primary, trunk, motorway` (связки `*_link` — класс основной дороги; `unclassified`, `living_street`, `road` → `residential`); `mode` — `bus, share_taxi, trolleybus, tram, light_rail, monorail, train, subway`; `stop_kind` и `facility_kind` — как у карты; `gateway_kind` — `road, transit`; `census_region` — `moscow, moscow_oblast` (исходная география переписи: «г. Москва» и «Московская область»); `period` — периоды интервалов из конфигурации в её порядке. Все коды, кроме периодов, фиксированы форматом.

Подробности:

- **Дуги.** Ребро пакета даёт прямую дугу (`reverse` = 0, направление файла `from_node → to_node`) и обратную. Дуги упорядочены для CSR по (исходный узел, конечный узел, `way_id`, `way_part`, `reverse`); петля даёт две дуги с одной парой узлов. `car` — проезд машиной в направлении дуги по `oneway`, у `pedestrian` всегда 0. `internal` — оба конца внутри региона и ребро не является дорожным входом: внутренний граф машины состоит из дуг с `car` = 1, `internal` = 1 и ненулевой скоростью класса. Поиск дуги по внешнему ID `<way>:<n>` идёт по колонке `by_edge` — это номера дуг в порядке (`way_id`, `way_part`, `reverse`), по две на ребро.
- **Привязка зданий** ([mobility.md](mobility.md#графы-и-пути)). `car_main` отмечает узлы основной компоненты сильной связности внутреннего графа машины: наибольшей среди компонент с исходящей дугой, при равенстве — с меньшим номером узла; только узлы с исходящей дугой. Здание привязывается к ближайшему узлу основной компоненты не дальше `building_node_max_m` (500 м) от представительной точки, тогда `road_node_depart` = `road_node_arrive`. Иначе для отправления берётся ближайший узел внутри региона с исходящей дугой машины, для прибытия — с входящей. Изолированное здание даёт явное «нет пути», а не путь от далёкого узла. Если подходящих узлов нет, в обеих колонках none.
- **Куски маршрутов.** Как в прототипе #35: маршрут строится из отрезков `transit_segments` по возрастанию номера. Пропуск номера или несовпадение концов закрывает кусок, поэтому прямой поездки через разрыв нет. Кусок содержит не меньше двух остановок. `segment_cm` — расстояние по прямой до следующей остановки куска, у последней — 0. Маршруты без кусков (в OSM-2021 нанесены без остановок или с одной) перечислены в отчёте качества (`sim.routes_without_pieces_list`).
- **Внешние входы.** У дорожного входа `arc` — прямая дуга ребра (или none, если ребра нет в графе), `inside_node` — конец ребра внутри региона, ближайший к точке пересечения границы (при равенстве — меньший номер). Ребро-хорда, оба конца которого снаружи, выездом не является ([mobility.md](mobility.md)): такие строки `gateways.csv` в таблицу не попадают, их число — в отчёте (`sim.road_gateways_without_inside_end`). Поэтому у каждого дорожного входа есть и дуга, и внутренний узел. У транспортного входа указаны остановка внутри региона и маршрут.
- **Перепись.** Таблицы хранят числа Росстата для исходных регионов: `moscow` — «г. Москва», `moscow_oblast` — вся «Московская область». Пояс пакета — лишь часть области, поэтому применение областных распределений к жителям пояса — допущение генератора (`estimated`, [population.md](population.md)), а не свойство этих наблюдаемых таблиц.
- **Единицы.** Скорости — мм/с (км/ч × 10⁶ / 3600 с округлением), длины и радиусы — см, время — с, доли и коэффициенты — 1/10 000. Интервалы движения — секунды, отсутствие движения — none.

Для `moscow-2021` 0.7.0: 20 таблиц, 76 МБ — 575 438 зданий, 7983 зоны, 406 048 узлов (398 850 в основной компоненте машины), 1 019 340 дуг, 13 206 остановок, 2486 кусков маршрутов (1061 маршрут без кусков перечислен в отчёте), 597 пересадок, 11 062 учреждения, 729 входов (12 дорожных рёбер-хорд без внутреннего конца исключены). У всех зданий есть узел привязки, 5418 зданий дальше 500 м от основной компоненты привязаны запасным правилом.

**Проверка** (`validate` и сам экспорт перед установкой пакета) повторяет правила загрузчика ядра. Индекс проверяется так: файл роли `sim` в паспорте — `estimated` с описанием оценки и путём `sim/index.json` (это проверяется и с `--metadata-only`), его источники — ровно объединение источников таблиц, размер не больше 1 МиБ (до чтения; индекс карты, из которого берётся плоскость, — не больше 8 МиБ), только известные поля, формат и версии, пакет совпадает с паспортом, плоскость (`origin_metric` и `metric_crs`) совпадает с индексом карты и проекцией паспорта, коды совпадают с форматом, таблицы ровно из списка и в его порядке. Вид данных должен быть по схеме (замена `observed` на `game_setting` допускается только в пакете `fixture`). Оценке нужны метод и неопределённость, источники должны быть в паспорте, синтетический источник не обосновывает `observed`. Для каждой таблицы проверяются, что это обычный файл внутри `sim/` (не символическая ссылка), размер (до чтения файла) и SHA256 по индексу, затем заголовок и колонки по [sim-core.md](sim-core.md#расчётный-пакет). Набор колонок полный и в порядке схемы, тип и число элементов совпадают, NaN и бесконечность отклоняются. Значения: диапазоны, коды, маски, ссылки в пределах таблиц (none только там, где разрешён), CSR начинаются с 0, не убывают и заканчиваются длиной пула, внешние ID уникальны, не равны меткам none/unknown, а строки идут в порядке стабильных ID (как в промежуточных файлах); суммарный размер таблиц — не больше 4 ГиБ (до чтения). Межтабличные сверки: жители зданий по зонам равны жителям зон, у зданий вне зон жителей нет; точка с ссылкой на зону лежит в квадрате этой зоны (допуск 1 м); у здания с функцией `unknown` все доли нулевые, у остальных сумма долей — 10 000 ± 40 (округление долей пакета), доминирующая функция имеет наибольшую долю; узел привязки здания внутри региона и имеет дугу машины нужного направления (исходящую для отправления, входящую для прибытия), а правило привязки пересчитывается по координатам с допуском 1 м; здание входит в учреждение не больше одного раза; дуги упорядочены, у каждого ребра пара дуг с общими атрибутами, `by_edge` — перестановка в своём порядке; `car_main` в точности совпадает с пересчитанной основной компонентой машины (с учётом скорости класса); дуга с `internal` = 1 соединяет узлы внутри региона, а дуга с обоими концами внутри может быть невнутренней, только если её ребро — дорожный вход; у `pedestrian` `car` = 0, а непешеходное ребро проезжаемо хотя бы в одну сторону; сумма весов автомобильного графа в децисекундах (длина / скорость класса) помещается в u32; длина дуги не меньше прямой между её узлами (допуск 20 см); у всех кусков маршрута один вид транспорта; длина перегона куска равна прямой между остановками (допуск 10 см); длины, площади и расстояния не равны меткам none/unknown; куски маршрутов идут подряд с номерами от 0, в каждом не меньше двух остановок; периоды разбивают сутки без пропусков и перекрытий; интервалы заданы для каждой пары (вид, период); возрастные группы переписи — ровно группы таблиц Росстата для каждого региона, жители по размеру домохозяйства согласованы с числом домохозяйств (1–5 — размер × число, 6+ — не меньше 6 × число), вложенные итоги не превышают общих (работающие ≤ указавшие статус ≤ всего, учащиеся ≤ указавшие статус обучения), в домохозяйствах 3+ не меньше трёх детей на домохозяйство, счётчики переписи не равны меткам, размеры домохозяйств — полная сетка 1–6 и 2–6 для каждого региона, домохозяйств с детьми не больше всех домохозяйств своего размера; поля дорожных и транспортных входов не перепутаны, транспортный вход ссылается на остановку внутри региона, которая стоит на куске своего маршрута того же вида рядом с внешней остановкой; у дорожного входа класс совпадает с классом дуги, дуга прямая (`reverse` = 0) и не внутренняя, при обоих концах внутри `inside_node` — ближайший к точке входа (допуск 1 м), а `inside_node` — один из её концов; маска `modes` остановки содержит вид каждого её куска маршрута; `way_id` меньше 2⁶³; `transfers.distance_cm` равно прямой между остановками (допуск 10 см), `walk_s` в точности равно времени по экспортированным `distance_cm`, `walk_speed_mm_s`, `transfer_overhead_s` и `walk_detour`; `inside_node` дорожного входа лежит внутри региона; ячейка начала пути `origin_cell_cm` делит сторону зоны на 1–16 ячеек (это проверяется и при загрузке конфигурации); `capacity` учреждений — только `unknown`.

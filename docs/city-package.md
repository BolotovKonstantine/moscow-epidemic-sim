# Формат паспорта городского пакета

На этапе 0 реализован паспорт версии 1, на этапе 1 в него добавлена роль `zones`: JSON с описанием региона, происхождением данных и перечнем файлов. Схема и CLI находятся в `tools/city_pipeline/`. Паспорт не содержит население или геометрию целиком: большие данные лежат рядом отдельными файлами, а проверка SHA256 читает их блоками.

Паспорт создаёт контракт между подготовкой данных и будущим загрузчиком игры. С этапа 1 пайплайн собирает реальный пакет (см. «Файлы пакета этапа 1»); загрузчика пакета в Godot и бинарных форматов расчётных таблиц для ядра ещё нет. Реализованы только производные участки карты для отображения (`.mtile`, см. «Участки карты») и их чтение в игре. Успешная проверка паспорта не означает, что пакет готов к игровой партии.

## Поля паспорта версии 1

| Поле | Значение |
| --- | --- |
| `schema_version` | Целое число 1; несовместимая версия отклоняется |
| `package_id`, `package_version` | Идентификатор пакета и версия его содержимого |
| `kind` | `fixture` для технического примера, `city_data` для подготовленных городских данных |
| `description` | Описание покрытия и назначения |
| `created_at` | Время создания с часовым поясом |
| `builder` | Имя и версия инструмента подготовки |
| `region` | Правило региона, 30 км буфера, системы координат и ссылка на файл границы |
| `sources` | Карточки происхождения исходников |
| `assets` | Файлы пакета, их роли, размеры, хеши и связи с источниками |

Схема: [city-package-v1.schema.json](../tools/city_pipeline/schemas/city-package-v1.schema.json). Поля с неизвестными именами отклоняются, чтобы опечатка не выглядела принятой настройкой. Версия схемы независима от версий пакета, ядра и Godot.

## Регион и координаты

`region.rule` фиксирует правило `moscow_admin_union_mkad_outer_buffer`; `buffer_meters` равен 30000. `storage_crs` — `EPSG:4326`, порядок географических координат — долгота, широта. `metric_crs` описывает выбранную метрическую проекцию обработки. `boundary_asset_id` указывает на существующий элемент `assets` с ролью `boundary`.

Это декларация правил обработки. Валидатор паспорта не проверяет геометрию; построение контура проверяет сборщик: проекция должна быть метрической, площадь внутри МКАД — в заданном диапазоне (850–900 км²), регион — содержать территорию внутри МКАД. Буфер 30 км и объединение с административной Москвой проверяются тестом на синтетическом городе.

В тестовом примере паспорта проекция обозначена как не выбранная: метрические операции в нём не выполняются. Реальный пакет `moscow-2021` использует `EPSG:32637`, контуры из OSM на 2021-01-01 и указывает источники и даты. Сезон и длительность игрового сценария паспорт не задаёт; они будут частью отдельной конфигурации сценария.

## Источники и файлы

Каждая карточка источника содержит ID, тип `external` или `synthetic`, URL, владельца, лицензию, дату данных, время получения, покрытие, формат, SHA256 исходника и версию обработки. Неизвестная дата данных обозначается `null`; хеш и лицензия необходимы для подготовленного пакета и не заменяются выдуманными значениями.

Файл содержит ID, роль, относительный путь, формат, размер в байтах, SHA256 и ссылки на источники. Путь записывается с `/` относительно каталога паспорта. Абсолютные пути, `..`, обратные слеши, неоднозначные компоненты и ссылки за пределы пакета не принимаются. Большие исходные выгрузки не обязаны лежать в пакете: их хеш сохраняется в карточке происхождения. Модельные параметры (интервалы движения, скорость пересадки) ссылаются не на OSM, а на синтетический источник `build-config-<package_id>` — саму конфигурацию сборки с её SHA256.

`data_kind` разделяет `observed`, `estimated` и `game_setting`. Для `estimated` обязательны `estimation.method` и `estimation.uncertainty`. Синтетический источник не может обосновывать файл с видом `observed`. Неизвестные значения внутри будущих таблиц должны иметь явное представление; их правила появятся вместе с форматами таблиц.

Роли файлов: граница, здания, дороги, транспорт, учреждения, население, зоны (`zones`), конфигурация сборки (`config`; обе добавлены на этапе 1, прежние паспорта остаются корректными) и отчёт качества. Набор доступных слоёв может быть неполным на промежуточных этапах. Валидатор не объявляет такой пакет играбельным и не подставляет отсутствующие слои нулевыми значениями.

## Проверки

CLI проверяет версию и обязательные поля, даты, уникальность ID и путей, связи с источниками и файл границы. В полном режиме дополнительно проверяются наличие, размер и SHA256 всех перечисленных файлов. JSON с повторяющимися ключами, NaN и Infinity отклоняется.

`--metadata-only` позволяет проверить паспорт до размещения больших файлов. Вывод явно указывает, что содержимое файлов не проверялось. Геометрия, связность графа, лицензирование производной базы и качество населения этой командой не подтверждаются.

Команды установки, проверки и тестов приведены в [AGENTS.md пайплайна](../tools/city_pipeline/AGENTS.md).

## Файлы пакета этапа 1

Промежуточные форматы: CSV и GeoJSON по одному объекту в строке, сжатые gzip без имени и времени в заголовке; координаты WGS84 с 7 знаками. Порядок строк — по стабильным ID. ID зданий и учреждений — ID OSM с префиксом типа (`w123`, `r456`, `n789`), рёбер дорог — `<way>:<номер участка>`, зон — `g<ix>_<iy>` (индексы квадрата 1 км в метрической проекции), маршрутов и stop_area — `r<relation>`.

| Файл | Роль · вид | Содержимое |
| --- | --- | --- |
| `boundary.geojson` | boundary · game_setting | Три объекта: `region` (граница пакета), `moscow_admin`, `mkad_outer`; площади в км² |
| `buildings.geojsonl.gz` | buildings · observed | Контуры зданий и исходные теги `building`, `building:levels`, `height`, `name` |
| `building_attributes.csv.gz` | buildings · estimated | Зона, Москва/пояс, внутри МКАД, площадь основания, этажность и её источник (`tag` — `building:levels` одним числом без округления, дробные сохраняются, `height` — высота в метрах или футах / 3 м, `default` — оценка по типу здания, в том числе при неоднозначных значениях вроде `3;5`), площадь этажей, источник функции (`tag`, `tag+poi` — основная функция по тегам, вторичные доли по точкам внутри, `poi`, `site`, `unknown`; функциональный тег самого здания вроде `shop` при `building=apartments` даёт вторичную функцию), доли функций `residential`, `work`, `retail`, `education`, `medical`, `transport`, `control`, `other` |

| `gateways.csv.gz` | transport · estimated | Внешние входы. `road` — точка пересечения границы региона ребром дороги, заходящим внутрь (касание границы снаружи не считается, у участка вдоль границы учитываются только его концы; строка на точку; `inside_ref`/`outside_ref` — концы ребра по сторонам границы, могут быть пустыми). `transit` — остановка маршрута в регионе, соседняя по маршруту с остановкой снаружи; ненайденные члены маршрута выходом не считаются |

Объединение и `building_ids` — пространственная эвристика, поэтому файл помечен `estimated`. Координаты учреждения-территории — вычисленная точка внутри контура, у учреждения-здания — точка здания, у точки — координаты узла |
| `zones.geojsonl.gz` | zones · estimated | Контур зоны, доли Москвы и территории внутри МКАД, жители, здания, здания без функции, жилая площадь, остановки и учреждения |
| `zone_links.csv.gz` | zones · estimated | Связи зон по видам: `road` — соседние зоны, границу между которыми пересекает ребро дороги внутри региона (ребро сначала обрезается границей; пересечения с линиями сетки вычисляются точно, поэтому учитываются все промежуточные зоны длинного ребра; проход ровно через угол даёт диагональную пару; участки вне региона связей не дают); `connections` — число таких рёбер, `min_length_m` — длина самого короткого. | `build_config.json` | config · game_setting | Точная копия конфигурации сборки, из которой собран пакет; её SHA256 совпадает с источником `build-config-<package_id>`, а URL источника указывает на файл в конкретном коммите (если он закоммичен без правок) |

Пустая ячейка CSV означает отсутствие значения (например, здание вне всех зон); `unknown` — явно неизвестное значение. Для синтетического пакета вид `observed` заменяется на `game_setting`, так как синтетика не является наблюдением.

## Участки карты

Формат версии 1 выбран в [#9](https://github.com/BolotovKonstantine/moscow-epidemic-sim/issues/9). Участки — производный слой только для отображения: они собираются из пакета и той же вырезки OSM, а модель их не читает. Пока реализован тестовый экспорт (`map-tile`, см. [tools/city_pipeline/AGENTS.md](../tools/city_pipeline/AGENTS.md)): обзор и по одному участку уровней 1 и 2 вокруг точки. Сборка всего региона и включение файлов в паспорт — задача #13.

**Плоскость.** Метрическая проекция пакета (`EPSG:32637`), 1 единица = 1 м, ось Y вниз. Начало `plane.origin_metric` — левый верхний угол, кратный 8 км. Координаты в плоскости карты: `x = E − x0`, `y = y0 − N`.

| Уровень | Участок | Содержимое | Упрощение |
| --- | --- | --- | --- |
| 0 | один на регион, начало (0, 0) | площади от 5 га, реки, магистрали (motorway, trunk, primary), магистральные железные дороги, границы региона и Москвы | 25 м |
| 1 | 8×8 км | площади от 2000 м², дороги до tertiary, реки, железные дороги, здания от 150 м² | площади 3 м, линии 4 м, здания 2 м |
| 2 | 2×2 км | всё без упрощения; данные выбора зданий | нет |

Участок `(ix, iy)` уровня с размером `s` занимает в плоскости карты квадрат от `(ix·s, iy·s)`; сетки уровней вложены. Вершины участка хранятся относительно этого угла. Площади и линии обрезаются по границе региона и участка. Здание целиком принадлежит участку, где лежит его представительная точка (`lon`, `lat` из `building_attributes.csv.gz`), и может выступать за край — это учтено в `bbox`. Тоннели дорог, рек и железных дорог не рисуются; метро — отдельный слой транспорта.

**Файл** `z<уровень>/<ix>_<iy>.mtile`: 8 байт `MESMTILE`, u32 версия формата, u32 длина заголовка, JSON-заголовок (UTF-8, дополнен пробелами до кратности 4), затем разделы. Числа little-endian; разделы идут сразу после заголовка, `offset` отсчитывается от начала файла и кратен 4. У раздела в заголовке: `name`, `dtype` (`f32`, `i32`, `json`), `shape` и `count` для массивов, `offset`, `size` (в файле), `raw_size` (после распаковки), `codec` — `deflate` (поток zlib, читается `PackedByteArray.decompress(raw_size, COMPRESSION_DEFLATE)`) или `none`. В заголовке также `package_id`, `package_version`, `level`, `tile`, `tile_size_m`, `origin` (угол в плоскости карты), `bbox` (в координатах участка), `classes`, `counts`, `attribution` — список: первая строка — подпись «© участники OpenStreetMap, ODbL», которую карта показывает всегда, затем владелец и лицензия каждого внешнего источника пакета из паспорта (для `moscow-2021` — OSM и GHS-POP: жители зданий в `pick.attrs` получены из сетки GHS-POP, CC BY 4.0).

| Раздел | Тип | Содержимое |
| --- | --- | --- |
| `area.xy`, `area.cls`, `area.tri` | f32 (V,2), f32 (V), i32 (T,3) | Площади подложки, разбитые на треугольники; код класса на вершину; порядок — порядок рисования |
| `line.xy`, `line.off`, `line.cls`, `line.tri` | f32 (V,2), f32 (V,2), f32 (V), i32 (T,3) | Ленты линий: две вершины на точку осевой линии, `off` — смещение в полуширинах (стык и квадратные концы); ширину задаёт шейдер по классу и масштабу |
| `building.xy`, `building.cls`, `building.tri`, `building.outline` | f32, f32, i32 (T,3), i32 (E,2) | Здания (уровни 1–2): вершины колец, треугольники заливки и отрезки контура по тем же вершинам |
| `pick.ring` | i32 (R,3) | Уровень 2: внешние кольца — строка здания в участке, первая вершина в `building.xy`, число вершин |
| `pick.bbox` | f32 (B,4) | Прямоугольник здания в координатах участка |
| `label.xy`, `label.angle`, `label.span`, `label.cls`, `label.weight` | f32 (N,2), f32 (N) ×4 | Подписи (#20): точка в координатах участка, угол текста в радианах в плоскости карты (текст не переворачивается, угол в (−π/2, π/2]), длина почти прямого участка линии под текстом в метрах (0 — точечная подпись), код класса, вес для порядка внутри класса (население, площадь, длина, класс дороги) |
| `label.text` | json | Тексты подписей — значения `name` OSM; в названиях административных округов «административный округ» сокращено до «АО» |
| `pick.attrs` | json | Колонки карточки: `id` (ID пакета), `name`, `function` и `function_source`, `levels` и `levels_source`, `footprint_m2`, `residents`, `zone_id`, `territory`. Функция — оценка, если `function_source` не `tag`; этажность — оценка при `levels_source=default`; жители всегда оценка, отсутствие строки в `population.csv.gz` означает 0 |

Подписи по уровням: в обзоре — Москва (`place=city` + `capital=yes`), административные округа (`admin_level=5`), городские округа (6), районы и поселения Москвы (8, точка подписи внутри Москвы), населённые пункты (`place=city|town|village|suburb|quarter|hamlet`), реки (`waterway=river`; длиннее 20 км ещё и одна подпись для обзора), водоёмы от 30 га, станции метро и железной дороги из `transit_stops.csv.gz` пакета; в участках 8 км — улицы от `tertiary`, в участках 2 км — все названные улицы от `residential` и `pedestrian` и реки. Подписи участка принадлежат участку, где лежит их точка. Подпись вдоль линии ставится в середине самого длинного почти прямого отрезка (отклонение от хорды не больше 8 % половины его длины). Какие подписи видны, решает игра по теме, масштабу и пересечениям.

Классы (код — позиция в списке, список — в `classes` заголовка): площади `farmland, residential, commercial, industrial, cemetery, grass, park, forest, water`; здания `unknown, residential, work, retail, education, medical, transport, control, other`; линии `stream, river, service, pedestrian, residential, tertiary, secondary, primary, trunk, motorway, tram, rail_minor, rail, boundary_moscow, boundary_region`; подписи `capital, okrug, municipality, city, town, district, village, suburb, hamlet, river_major, river, water, street_major, street, metro, rail_station`. Классы дорог — из `highway` (связки `*_link` — класс основной дороги; `unclassified`, `living_street`, `road` → `residential`). Подложка из OSM: `water` — `natural=water`, `waterway=riverbank`, `landuse=reservoir|basin`; `forest` — `landuse=forest`, `natural=wood`; `park` — `leisure=park|garden|golf_course`, `landuse=recreation_ground|village_green`; `grass` — `landuse=grass|meadow`, `natural=grassland|scrub|heath`; `river` — `waterway=river|canal`; `rail_minor` — `railway=rail` с `service` и `narrow_gauge`; `tram` — `railway=tram|light_rail|monorail`.

**Чтение в игре** — `game/scripts/map/` ([game/AGENTS.md](../game/AGENTS.md)): игра отклоняет индекс или участок другой версии формата, с SHA256, пакетом, уровнем или классами, не совпадающими с индексом, и разделы, выходящие за файл или ссылающиеся на несуществующие вершины, — с понятным сообщением, без падения.

**Индекс** `index.json`: `format` = `mesim-map-index`, `format_version`, пакет и его источники, `metric_crs`, `plane`, `levels`, `classes`, `attribution` и список `tiles` с уровнем, индексами, путём, размером, SHA256, `bbox` в плоскости карты и счётчиками. Повторный экспорт из тех же файлов даёт те же байты. `map-tile` отказывается работать, если переданная конфигурация не совпадает с `build_config.json` пакета: вырезка OSM хранится по хешу конфигурации, и другая конфигурация подставила бы чужую вырезку или проекцию.

Контуры `boundary.geojson` округлены до 7 знаков WGS84; после перевода в метры у границы региона `moscow-2021` 0.1.0 есть микросамопересечение, поэтому карта исправляет контуры `make_valid`. На расчёты пакета это не влияет: они выполняются по исходной метрической границе.

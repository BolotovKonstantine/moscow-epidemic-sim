# Малые сцены и эталонные выходы

Синтетические сцены для сверки нативного ядра с простой независимой реализацией модели (`game/sim/`). Данные сцен вымышлены, реальных людей и мест в них нет. Тест — [tests/model/mobility_reference.gd](../model/mobility_reference.gd), команды — в [game/AGENTS.md](../../game/AGENTS.md).

| Каталог | Что проверяет |
| --- | --- |
| `mobility_edge/` | Пограничные случаи движения с параметрами, удобными для ручного счёта (1 м/с, коэффициент пешего пути 1,0): перегрузка маршрутки вместимостью 1 и порядок очереди, отмена после предела ожидания при полных рейсах и без рейсов, одностороння улица, изолированное здание, пересадка, путь от остановок дома, ночная смена через полночь, транспортный и дорожный внешние входы, житель без места |
| `mobility_mini/` | Мини-город с параметрами [mobility.md](../../docs/mobility.md): сетка дорог с односторонним участком, метро в 2 вагона и автобус с пересадкой, изолированная школа, оба вида входа, ночные смены; 24 жителя, двое суток |

В каждом каталоге `scene.json` — вход, `expected.json` — выход эталона. Эталонный выход меняется только осознанно, вместе с правилами ниже: тест сравнивает его побайтно, а `--update` перезаписывает.

## Сцена движения: схема версии 1

Все поля обязательны, неизвестные поля — ошибка. Время — целые секунды от начала сценария (полночь нулевых суток), координаты — метры в плоскости сцены, `[x, y]`. Числа, которые схема называет целыми, должны быть целыми.

| Поле | Смысл |
| --- | --- |
| `schema_version` | `1` |
| `name`, `seed` | Имя сцены; seed сессии (поток транспорта — ключ `stream_key(seed, 4)`) |
| `duration_s` | Длительность; рейсы отправляются и поездки начинаются только раньше неё |
| `checkpoints_s` | Строго возрастающие контрольные времена в `[0, duration_s]` |
| `params` | `walk_speed_mps`, `walk_detour`, `parking_s` (на каждом конце у здания), `attach_radius_m`, `access_radius_m`, `access_stops_max`, `transfer_radius_m`, `cell_size_m`, `board_penalty_s`, `max_wait_s`, `walk_only_max_s`, `walk_fallback_max_s` — значения `game_setting` / `estimated` из mobility.md |
| `periods` | Периоды суток `{name, start_s}`, начала строго возрастают в `[0, 86400)`. До самого раннего начала действует последний период, поэтому полночь — граница, только если какой-то период начинается в 0 |
| `modes` | Вид транспорта → `{speed_kmh, capacity, wagons (1–16), headway_s: [по периоду, 0 — нет движения]}` |
| `road_nodes`, `road_edges` | Узлы `[x, y]`; рёбра `{from, to, length_m (целое), speed_kmh, oneway}` |
| `buildings` | Здания `[x, y]`; ID — номер в массиве |
| `stops`, `stop_areas` | Остановки `{x, y, outside}`; группы пересадок (не меньше двух остановок) |
| `routes` | `{mode, stops: [...]}` — одно направление; обратное — отдельный маршрут |
| `gateways` | `{kind: "road", node}` или `{kind: "transit", stop}` (остановка внутри региона, где пассажир пересекает границу) |
| `residents` | `{home, profile: "car"/"other", place: null / {building} / {gateway}, arrive_by_s, leave_at_s}`; ID жителя — номер в массиве |

## Правила эталона

Эталон — прямое прочтение [mobility.md](../../docs/mobility.md) и [sim-core.md](../../docs/sim-core.md) без ускорений: Дейкстра вместо CH, дерево остановок на каждую поездку вместо общего кеша, двоичная куча вместо очереди ядра. Где документы оставляли выбор, он закреплён здесь, чтобы C++ мог совпасть побитово.

**Времена и округление.** Каждый участок округляется до целой секунды отдельно, половина — вверх: пешком `round(d × walk_detour / walk_speed_mps)`, ребро дороги и перегон `max(1, round(d × 3,6 / speed_kmh))`, где перегон — прямая между остановками. Пешая пересадка — не короче 1 с. Расстояния — `sqrt` в double.

**Привязка к дорогам.** Здание — к ближайшему узлу наибольшей компоненты сильной связности (при равном размере — с меньшим наименьшим узлом) не дальше `attach_radius_m`, иначе к ближайшему узлу любой компоненты; при равном расстоянии — меньший номер. Дорожный вход — свой узел, транспортный — привязка его остановки. Время машины — кратчайший путь плюс `parking_s` на каждом конце у здания (у входа парковки нет).

**Транспорт.** Узлы дерева: остановка «можно сесть», остановка «только что вышел», позиция маршрута «в рейсе». Посадка — на позициях, кроме последней, если в периоде плана есть движение: стоимость `⌊h/2⌋ + board_penalty_s`, время `⌊h/2⌋`. Перегон — к следующей позиции. Выход — на любой позиции, кроме первой, только на остановке внутри региона. После выхода — посадка на той же остановке (0 с) или пешая пересадка на остановку той же группы `stop_areas` либо ближе `transfer_radius_m`. Дейкстра по (стоимость, номер узла), запись заменяется только при строго меньшей стоимости.

1. Начальные остановки — внутри региона, не дальше `access_radius_m + cell_size_m·√2/2` от центра ячейки начала пути; стоимость и время — пешком от центра ячейки.
2. Конечные — до `access_stops_max` ближайших внутри региона, не дальше `access_radius_m` от цели (по расстоянию, затем номеру). Выбирается наименьшая стоимость до выхода плюс отход пешком, при равенстве — меньший номер остановки.
3. Если начальная остановка пути дальше `access_radius_m` от самой точки начала, путь строится заново деревом от точки начала (радиус `access_radius_m`, `tree: "origin"`).
4. Время пути — подход от самой точки + время ядра пути (от начальной остановки до выхода) + отход.

**Выбор вида.** Профиль `car` едет на машине, если путь по дорогам есть. Иначе: пешком, если не дольше `walk_only_max_s` и не медленнее транспорта; иначе транспортом; иначе пешком до `walk_fallback_max_s`; иначе «нет пути» — житель остаётся дома, `no_path`. Путь туда планируется для периода `arrive_by_s`, обратно — для периода `leave_at_s`; один план на все сутки.

**Расписание.** Каждые сутки `d`: выезд в `d·86400 + arrive_by_s − время пути туда` (если не раньше 0), обратно в `d·86400 + leave_at_s` (на сутки позже, если `leave_at_s < arrive_by_s`). Поездка начинается, только если житель в её начальной точке; поездки, чьё время прошло, пока он был в пути, или начинающиеся из другой точки, пропускаются. Без места или без пути поездок нет.

**Рейсы.** Как в прототипе #35: от первой остановки с интервалом периода. Фаза разыгрывается в первом периоде с движением и после каждого периода без движения: `below(h)` со счётчиком (маршрут, n, время начала розыгрыша, 1). Если сдвиг выходит за границу периода, фаза разыгрывается заново с этой границы. Следующее отправление — через интервал; если оно на границе периода или за ней, действует уже интервал нового периода (`max(граница, t + h₂)`), период без движения останавливает маршрут на своём начале. Номер рейса в суточном расписании — порядок (отправление, маршрут) среди отправлений этих суток, ID события — `2³¹ + номер`. Время прибытия на следующую позицию — плюс перегон.

**События.** Ключ — (время, ID, сутки рейса); жители (`ID < 2³¹`) раньше рейсов. `advance_to(t)` исполняет события строго раньше `t`; контрольное состояние на `t` — после них. У жителя одно ожидающее событие, устаревший ключ отбрасывается. Нулевые участки (подход 0 м, пересадка на той же остановке, выезд ровно в момент прибытия) выполняются в том же обработчике.

**Поездка.** Машина и пешком — один участок. Транспорт: подход → очередь на позиции посадки → рейс → после выхода пересадка пешком к следующей очереди или отход к цели. Очередь — в порядке прихода. В событии рейса сначала выходят приехавшие (по возрастанию ID), затем садятся ждущие, пока число пассажиров меньше вместимости. Вагон — `below(wagons)` со счётчиком (житель, n, время посадки, 0). Предел ожидания — событие жителя через `max_wait_s` после прихода в очередь: отмена, уход из очереди и возвращение в начало поездки за (время с начала поездки − всё время ожидания), состояние `return`. Пересчёта на другой путь нет (#44).

**Состояния.** В каждый момент житель ровно в одном: `home`, `place`, `outside`, `walk`, `car`, `wait`, `ride`, `return`.

## Выход (`expected.json`)

Одна запись массива — одна строка. Все числа — целые.

| Ключ | Содержимое |
| --- | --- |
| `plans` | На жителя `{no_path, trips: [туда, обратно]}`; поездка — `{mode, time_s}`, у транспорта ещё `access_s`, `egress_s`, `start_stop`, `end_stop`, `tree` и `rides: [{route, board, alight, walk_after_s}]` |
| `runs` | `[сутки, номер, маршрут, отправление]` |
| `checkpoints` | `{t, counts, residents, runs, queues}`: место каждого жителя (`["home", здание]`, `["place", здание]`, `["outside", вход]`, `["wait", маршрут, позиция, время предела]`, `["ride", сутки, номер, вагон]`, `[walk/car/return, время конца участка]`); рейсы с пассажирами `[сутки, номер, маршрут, следующая позиция, [ID]]`; очереди `[маршрут, позиция, [ID по порядку]]` |
| `intervals` | Интервалы присутствия в группах (рейс, вагон): `[сутки, номер, маршрут, вагон, житель, позиция посадки, позиция выхода, время посадки, время выхода]`, по возрастанию |
| `log` | Журнал всех жителей в порядке исполнения: `depart` (вид, 0 — туда / 1 — обратно), `queue` (маршрут, позиция), `board` / `alight` (сутки, номер рейса, вагон), `arrive` (место), `cancel` (маршрут, позиция), `returned` |
| `violations` | Нарушения инвариантов по ходу прогона; в эталонном выходе — пусто |

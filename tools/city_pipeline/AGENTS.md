# city_pipeline — городские пакеты

Общие правила — в [../../AGENTS.md](../../AGENTS.md). Источники и правила данных — в [../../docs/data.md](../../docs/data.md), формат паспорта и файлов пакета — в [../../docs/city-package.md](../../docs/city-package.md).

## Устройство

- `schemas/city-package-v1.schema.json` — JSON Schema паспорта, версия 1; `schemas/build-config-v1.schema.json` — схема конфигурации сборки, проверяется в `fetch` и `build` до любой работы (вместе с ограничениями заголовка расчётной таблицы на `package_id` и `package_version`).
- `manifest.py` — структурная и смысловая проверка паспорта, файлов и SHA256, для роли `map` — ещё индекса и каждого участка карты, для роли `sim` — индекса и каждой расчётной таблицы (`simtables.validate_sim_index`). Не загружает данные из сети.
- `sources.py` — реестр источников `data/manifests/sources.json`: загрузка в `data/raw/` и проверка SHA256.
- `osm.py` — чтение OSM за один проход pyosmium; `geo.py` — проекции и граница региона.
- `buildings.py` (функции и этажность), `population.py` (сетка → здания), `roads.py` (дорожный граф), `transit.py` (маршруты, отрезки, пересадки), `facilities.py`, `zones.py` (сетка зон).
- `build.py` — сборка пакета; `report.py` — отчёт качества; `writers.py` — детерминированная запись файлов.
- `maptiles.py` — формат участков карты (`.mtile`), триангуляция площадей и ленты линий (по уровням рисования мостов — `line_level`, `level_ribbons`, #23); `mapbuild.py` — подложка из OSM и сборка участков из пакета (`MapSource` один раз готовит слои уровней, индексы и группы подписей, линии маршрутов — пути отношений `route` из вырезки OSM и схему метро из `transit_segments`, данные обзора — зоны, остановки и учреждения (#16); `export_region_tiles` пишет весь регион и проверяет покрытие, `build` вызывает его для каталога `map/` пакета); `maplabels.py` — подписи (названия из OSM и станции пакета, якоря вдоль линий). Формат — в [docs/city-package.md](../../docs/city-package.md#участки-карты).
- `mtab.py` — формат расчётной таблицы `.mtab` (запись и структурная проверка, [docs/sim-core.md](../../docs/sim-core.md#расчётный-пакет)); `simtables.py` — схема таблиц `sim/`, экспорт из файлов пакета (дорожный граф CSR, привязка зданий к узлам машины, куски маршрутов, модельные параметры, перепись) и валидатор по правилам загрузчика ядра; `census.py` — разбор пяти таблиц переписи Росстата (xlsx). Состав таблиц — в [docs/city-package.md](../../docs/city-package.md#расчётные-таблицы).
- `__main__.py` — CLI `validate`, `fetch`, `build`, `map-tile`.
- Конфигурация сборки — `data/manifests/moscow-2021.json`. Ключи OSM из `poi_functions`, `site_functions` и `facilities.kinds` автоматически добавляются в фильтр чтения; если объект подходит под несколько ключей, решает первый по алфавиту. Модельные параметры (интервалы транспорта, скорость пересадки, параметры поездок `mobility`) — в её разделе `model_assumptions`; их можно менять, они попадают в пакет как `game_setting` (коэффициент `walk_detour` — `estimated`). Таблицы переписи — источники ролей `census_*` в разделе `sources`.
- `tests/fixtures/map_tile/` и `tests/fixtures/map_stream/` — синтетические наборы участков карты для тестов загрузчика и подгрузки по камере в Godot; пишутся `tests/city_pipeline/map_fixture.py` тем же кодом, что и экспорт (`.venv/bin/python -m tests.city_pipeline.map_fixture`), unit-тест требует, чтобы закоммиченные файлы совпадали с пересборкой: меняя формат или запись участков, пересобери фикстуру.
- `tests/fixtures/city_package/` — синтетический пример паспорта; `tests/city_pipeline/synthetic_city.py` — синтетический мини-город для теста сборки. Ни то ни другое не является картой региона.
- Большие файлы находятся в игнорируемых каталогах `data/raw/`, `data/processed/`, `data/packages/`.

## Окружение и команды

Из корня репозитория, Python 3.14 из Homebrew. Используй только собственное `.venv`. Для `build` нужна утилита `osmium` (osmium-tool, Homebrew); тесты её не требуют.

```sh
/opt/homebrew/bin/python3.14 -m venv .venv
.venv/bin/python -m pip install -r tools/city_pipeline/requirements.txt
.venv/bin/python -m unittest discover -s tests/city_pipeline -v
.venv/bin/python -m tools.city_pipeline validate tests/fixtures/city_package/manifest.json
.venv/bin/python -m tools.city_pipeline validate tests/fixtures/city_package/manifest.json --metadata-only
.venv/bin/python -m tools.city_pipeline fetch data/manifests/moscow-2021.json
.venv/bin/python -m tools.city_pipeline build data/manifests/moscow-2021.json
.venv/bin/python -m tools.city_pipeline validate data/packages/moscow-2021-0.7.0/manifest.json
.venv/bin/python -m tools.city_pipeline map-tile data/manifests/moscow-2021.json   # тестовые участки карты
.venv/bin/python -m tools.city_pipeline map-tile data/manifests/moscow-2021.json --at 37.5,55.6 --out data/processed/map-test
.venv/bin/python -m tools.city_pipeline map-tile data/manifests/moscow-2021.json --all --out data/processed/map-region   # весь регион, как в пакете
```

`fetch` скачивает около 735 МБ (OSM ЦФО на 2021-01-01, тайл GHS-POP и пять таблиц переписи) и отказывается принимать файл с другим SHA256. `build` на эталонном Mac (M1, 16 ГБ) занимает ~3 мин 45 с, из них ~2 мин — участки карты всего региона (замер 9 октября 2026, `moscow-2021` 0.2.0, с первой вырезкой OSM ~30 с), пиковая память ~2,7 ГБ; для 0.4.0 (12 октября 2026) — ~6,7 мин с готовой вырезкой OSM и ~9,5 мин с новой, максимум резидентной памяти 2,1–2,3 ГБ (пиковый footprint по `time -l` — до 4,5 ГБ); причину роста против 0.2.0 сверх экспорта карты (+1 мин, см. ниже) не разбирали; для 0.5.0 (уровни мостов #23, 12 октября 2026) — ~5,8 мин с готовой вырезкой OSM, максимум резидентной памяти 2,3 ГБ, пиковый footprint 4,5 ГБ; для 0.6.0 (распределение остатка населения #53, 13 октября 2026) — ~4,1 мин с готовой вырезкой OSM, максимум резидентной памяти 2,5 ГБ, пиковый footprint 4,5 ГБ; для 0.7.0 (расчётные таблицы `sim/` #36, 16 октября 2026) — 7 мин 11 с с новой вырезкой OSM, максимум резидентной памяти 2,7 ГБ, пиковый footprint 4,5 ГБ; экспорт `sim/` с проверкой — ~18 с, 20 таблиц, 76 МБ (здания 35,1, дуги 29,6, узлы 13,8 МБ), повторный экспорт совпал побайтно, `validate` всего пакета — ~6 с; результат — `data/packages/<package_id>-<version>/` с `manifest.json` и `quality_report.md`. Файлы пишутся в уникальный временный каталог `<пакет>.<случайное>.partial` рядом и подменяют прежний пакет только после проверки паспорта; при ошибке временный каталог удаляется, чужие каталоги не трогаются: прежний каталог заменяется, только если он пуст или его `manifest.json` читается и совпадает по `package_id` и `package_version`. Прежний пакет на время установки переименовывается в резервную копию и возвращается, если установка не удалась. Промежуточные файлы — в `data/processed/<package_id>/<version>-<хеш конфигурации>/`; одинаковые сборки, запущенные одновременно, ждут друг друга (блокировка `.lock`), а любые сборки в один каталог пакета устанавливают его по очереди (блокировка `data/packages/.<пакет>.lock`). Если процесс убит, временные каталоги `*.partial` и `*.previous` можно удалить вручную. `SOURCE_DATE_EPOCH` фиксирует `created_at`, чтобы повторная сборка совпала побайтно и по паспорту.

`map-tile` требует собранного пакета и его вырезки OSM в `data/processed/` (её создаёт `build`) и держит ту же блокировку каталога пакета, что `build`: сборка и экспорт одного пакета идут по очереди. Он пишет обзор региона и участки уровней 1 и 2 вокруг точки `--at` (по умолчанию центр Москвы) в `data/processed/map-test/`: `index.json` и `z<уровень>/<ix>_<iy>.mtile`. На эталонном Mac — ~45 с, из них ~25 с — подписи (второй проход по вырезке OSM и якоря улиц), пиковая память ~1,6 ГБ; для центра Москвы обзор занимает 3,5 МБ, участок 8 км — 1,8 МБ, участок 2 км — 0,8 МБ (замер 8 октября 2026, `moscow-2021` 0.1.0). Повторный запуск даёт те же байты.

`map-tile --all` пишет тот же набор, что `build` кладёт в `map/` пакета: обзор и все участки уровней 1 и 2, задевающие регион, и печатает сводку размеров и проверок покрытия (при нарушении — ошибка). Оба режима `map-tile` пишут набор во временный каталог `.<имя>.*.partial` рядом и подменяют прежний только целиком; заменяется лишь пустой каталог или прежний набор участков (с `index.json` карты), чужой непустой каталог — ошибка. Перед подменой каталог проверяется ещё раз под блокировкой `.<имя>.lock` рядом: каталог, появившийся за время сборки, тоже не затирается. Для `moscow-2021` 0.2.0: 1 + 150 + 2061 участок, 163 МБ (медиана участка 8 км — 0,15 МБ, 2 км — 0,035 МБ; самый тяжёлый — обзор, 3,5 МБ), индекс 1,1 МБ; на эталонном Mac ~2 мин, пиковая память ~1,7 ГБ (замер 9 октября 2026). Для 0.4.0 со слоями #16: 176 МБ (обзор — 4,0 МБ: 7983 зоны, 12 576 остановок, 11 062 учреждения), ~3 мин против ~2 мин 10 с без слоёв на тех же данных, из них ~20 с — второй проход по вырезке за путями маршрутов; максимум резидентной памяти ~2,1 ГБ (замер 11 октября 2026); повторный экспорт совпал с `map/` пакета побайтно. Сборка последовательная: так проще сохранить побайтную воспроизводимость.

Полная проверка включает существование файлов, размер и SHA256. `--metadata-only` проверяет структуру и связи ID, но не открывает файлы данных. Код возврата 0 — успех, 1 — некорректные данные или ошибка, 2 — неверные аргументы CLI.

Не меняй среду других проектов. При изменении схемы добавляй проверки совместимости и обновляй документ формата. Версия паспорта не является версией ядра или Godot. Новый источник — сначала карточка в `sources.json` с SHA256, потом код.

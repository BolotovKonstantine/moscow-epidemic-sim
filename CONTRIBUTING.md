## Задачи и изменения

Создай Issue через подходящую форму: задача, ошибка, источник данных или обсуждение решения. Укажи цель, этап, модули, границы, критерии приёмки, способ проверки и зависимости. Новые крупные механики и изменения архитектуры сначала согласуются с автором в Issue.

Одна задача даёт отдельно проверяемый результат. Рабочие Issues добавляются в [Project](https://github.com/users/BolotovKonstantine/projects/7): `Todo` → `In Progress` → `Done`. Этап задачи задаётся milestone репозитория, статус — столбцом доски. Карточки этапов дают обзор; они не заменяют конкретные задачи. Исполнитель обновляет статус вручную; `Done` для реализации означает выполненные критерии и слитый PR.

Для внешнего вклада создай fork и ветку `<тип>/<кратко>`, затем pull request по шаблону репозитория. В описании объясни проблему, изменение, связь с Issue, проверку и ограничения. `Closes #N` — только для полного решения; `Refs #N` — для частичного. Для небольших исправлений документации и PR Dependabot отдельная Issue необязательна.

Только автор сливает в `main` и выпускает релизы. ИИ-ассистенты коммитят и пушат только по просьбе автора. Документация, Issues и описания PR — на русском; файлы и идентификаторы — на английском. Обновляй документацию вместе с поведением. Команды сборки и проверки находятся в `AGENTS.md` модулей `game/`, `native/`, `tools/city_pipeline/`; правила CI — в `.github/AGENTS.md`.

Перед review проверь критерии Issue, релевантные тесты и CI на последнем commit. Для нативного кода нужна ручная сборка/smoke; для изменений экспорта — релевантная проверка платформы. Описание содержит команды, commit и результат. Правила для ассистентов и инварианты модели — в [AGENTS.md](AGENTS.md).

## Данные и лицензия

Собственный код и документация распространяются по [MIT](LICENSE). Сторонние данные, библиотеки и ресурсы сохраняют свои лицензии. Укажи владельца источника, URL, даты, покрытие и условия использования; неизвестная лицензия не разрешает распространение. Предположения модели и оценки отделяются от наблюдаемых значений.

Большие выгрузки, промежуточные данные и собранные пакеты хранятся вне Git. В репозитории — скрипты получения, манифесты и небольшие разрешённые фикстуры. Секреты и персональные записи реальных жителей не добавляются; население синтетическое.
